# QA Checklist

Run this checklist before calling a carousel final.

## Strategy

- [ ] Audience is specific.
- [ ] Learning outcome is concrete.
- [ ] Angle is distinct from recent posts.
- [ ] Objective and CTA match.
- [ ] Brand presence is intentional rather than forced.

## Research and claims

- [ ] Time-sensitive claims were checked recently.
- [ ] Source dates are recorded.
- [ ] Facts, observations, and interpretations are separated.
- [ ] Absolute predictions were softened unless evidence supports them.
- [ ] Brand, product, ingredient, and regulated claims come from approved sources.

## Narrative

- [ ] Cover makes one clear promise.
- [ ] Context explains why the topic matters.
- [ ] Each slide teaches one distinct idea.
- [ ] No two slides repeat the same lesson.
- [ ] Transitions make sense without the caption.
- [ ] Closing gives a useful recap, checklist, or relevant CTA.

## Copy

- [ ] Headlines are scannable.
- [ ] Body copy is short enough for mobile.
- [ ] Tone sounds personal, practical, and grounded.
- [ ] Spelling, punctuation, and numbering are correct.
- [ ] UK English is used when English is requested unless told otherwise.
- [ ] Three caption options are present when required.

## Visual system

- [ ] Canvas is 1080 × 1350 px.
- [ ] Safe margins are consistent.
- [ ] Typography hierarchy is stable.
- [ ] Trend numbers use one size, colour, and position system.
- [ ] Background, lighting, and colour grading match.
- [ ] Accent colour is controlled.
- [ ] Glass, garnish, bottle, and logo are not accidentally cropped.
- [ ] Text does not touch edges or clash with imagery.
- [ ] Visuals support the lesson rather than merely decorate it.

## Revision integrity

- [ ] Only requested slides or elements changed.
- [ ] Approved slides were preserved.
- [ ] Change log matches the delivered draft.
- [ ] No old version was accidentally reintroduced.

## File integrity

- [ ] Every file exists and has a unique name.
- [ ] Every image opens or decodes successfully.
- [ ] Pixel dimensions were inspected.
- [ ] Colour mode is suitable for publishing.
- [ ] Slide count matches the manifest.
- [ ] Filenames sort in the intended upload order.
- [ ] ZIP integrity was tested after packaging.
- [ ] Package contents were inspected after extraction.

## Delivery

- [ ] Draft and final files are separated.
- [ ] Final package contains no audit screenshots or working files.
- [ ] Caption, alt text, sources, and upload notes are included.
- [ ] Editable master link is included when available.
- [ ] User approval is recorded.
- [ ] Auto-publish remains blocked until explicit final approval.

## Failure patterns and fixes

| Failure | Why it happens | Fix |
|---|---|---|
| Generic trend list | Research was converted directly into slides | Define audience lesson and editorial angle first |
| Repetition with earlier post | Topic similarity was not audited | Compare against recent content before storyboarding |
| “Expert” tone feels inflated | Claims are written as certainty | Use sourced facts plus personal-observation framing |
| Too many themes | Slide count is treated as a target | Merge overlaps and keep only distinct lessons |
| Beautiful but not useful | Visual direction preceded strategy | State what the viewer learns before designing |
| Inconsistent numbers or colours | No locked component system | Define tokens and repeated positions before production |
| Cropped glass or garnish | Image review focused on aesthetics only | Add subject-integrity checks to visual QA |
| Wrong upload order | Ambiguous filenames | Use zero-padded filenames and a manifest |
| Corrupted image inside package | Only filename and size were checked | Decode every image and test ZIP extraction |
| Draft files reach final package | Working directory was reused | Export to a clean final directory |
| Canva automation drifts | Template is a flattened image | Rebuild with editable, named layers and variable fields |
